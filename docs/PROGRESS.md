- **Blocker (owner):** release `v0.0.1-fase0` failed by design — the GitHub secrets `KEYSTORE_PASSWORD`, `KEY_ALIAS` and

  fails (by design). Signed APKs come from `release.yml` until the owner creates it (docs/06-arranque.md §1).
- Pixel 8 (the Pixel 8) in use since the owner allowed it (2026-10-16 evening). Its sustained run and a matrix
  repeat need a lit scene (the phone lay face down) and must run unplugged.
- **4K60 10-bit is not universal**: the Pixel 8 HAL refuses HLG10 above 30 fps. The REQ-NFR-001 decision will likely
  be "4K30 10-bit base, 4K60 10-bit where the HAL accepts it" (spike-report.md); needs the other phones.
- The OPPO (wireless adb) disconnected during the session and no longer advertises over mDNS: no device measurement yet.
- The 10-bit path samples camera frames through `samplerExternalOES` (driver YUV→RGB). If a driver drops to 8-bit
  precision there, `GL_EXT_YUV_target` raw sampling will be needed (availability recorded per phone).
- **F-Droid build (owner decision):** F-Droid runs `assembleRelease` without our key, but `checkReleaseSigning` refuses
  any unsigned release. Before submitting the recipe an explicit opt-in for an unsigned (never debug-signed) release is
  needed, e.g. a Gradle property set by the recipe's `gradleprops`.
- **Maker LUT downloads (decided, D44: in-app download after confirmation):** OPPO's site terms also forbid "deep-link" or automatic access to obtain
  materials "by any means not purposely made available through the Site". The catalogue fetches the same zip the
  official page links, only after the user confirms and with the terms link shown; whether that is acceptable, or the UI
  should only open the official page and let the user import the file (REQ-COL-007 allows both), is the owner's call.
  The vendor zip can change at any time: a new checksum then fails the download until the catalogue is updated.
